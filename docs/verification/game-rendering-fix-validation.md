# 0.3.1 地牢同层地图覆盖修复验证

日期：2026-11-06。针对“同一层探索新房间时，旧房间及下楼梯被覆盖”的反馈。测试环境为本机 Windows、内置 Chromium 浏览器、1280 × 720 视口；使用本地预览账号既有角色的存档副本运行真实 TeaVM 游戏。副本由仅监听回环地址的隔离测试服务提供，测试保存写入副本文件，不连接业务数据库。存档、账号信息及原始备份均未入库。

## 根因与修改范围

地图存档中的出口仍是 `REGULAR_EXIT`，地形值为 `8`。旧画面中的覆盖来自局部顶点复制：当前 TeaVM typed-array FloatBuffer 的批量 `put` 没有按源缓冲的非零 position 读取，导致上传其他位置的顶点。Web `Vertexbuffer` 改为逐项读取绝对源索引，保持上传的目标偏移和长度，并保留源 position/limit。

游戏生成逻辑、原生存档格式、账号隔离及同步协议没有改动。不整体切换未经验证的其他 Web fork。固定上游提交和对应源码继续随产物提供，Java 本地改动已登记到 `UPSTREAM.json`。

## 可重复的前后对照

1. 保留旧编译产物，从同一份第一层存档进入游戏，使用右方向键并点击东侧房门，再沿相邻弯曲走廊移动。
2. 旧版在该路线末端出现横向水面覆盖墙、房间和黑色区域，见[旧版截图](images/game-rendering/before-exploration.png)。
3. 修复版重复同一路线，墙、水面、走廊与楼梯保持原位置，见[修复后截图](images/game-rendering/after-exploration.png)。测试服务核对探索后的地形数组与初始数组一致，两处楼梯类型和值均保持不变。
4. 点击原房间的下楼梯，实际进入第二层，界面和原生存档的深度均为 `2`，见[下楼截图](images/game-rendering/after-downstairs.png)。
5. 方向键与鼠标路径均可继续操作，未捕获浏览器 error/warn。测试前后，本地预览账号原快照的 revision 及全部 snapshot 内容完全相同；测试未消耗用户的原进度。

## 交付与边界

本地新进入游戏即可加载修复产物；已经打开的游戏需先同步进度，再离开并重新进入。服务器升级必须重新构建游戏，按 [Windows 更新流程](../windows-update.md) 生成候选、备份和切换；仅更新源码而不构建不会替换游戏脚本。0.3.0 到 0.3.1 无新增数据库迁移，也不需要重建角色。

本次验证针对已复现的地图绘制缺陷与第一层到第二层的路径，不代表全部楼层、物品、角色、实体手机和所有浏览器已经验证。此源码电脑未连接或升级用户的另一台服务器。
