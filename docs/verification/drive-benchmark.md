# 云盘大文件本地基准

记录日期：2026-11-04。测量时间：23:40:40（Asia/Shanghai，UTC 15:40:40）。本记录使用合成数据验证 HTTP 分片传输、磁盘持久化和流式下载；不构成生产网站或公网网速验收。

## 可重复执行的工具

仓库根目录运行 [benchmark-drive.ts](../../scripts/benchmark-drive.ts)：

```powershell
# 预先设置 TEST_DATABASE_URL，或 AUTH_TEST_DATABASE_URL。
# 该地址必须是本机 PostgreSQL 的 *_test 数据库，并有创建/删除测试库权限。
npx tsx scripts/benchmark-drive.ts --size-mib 512 --parallel 4
```

- 默认 512 MiB、4 路并发；`--size-mib` 接受 1–65536，`--parallel` 接受 1–8；固定分片为 16 MiB，最后一片可以较短。
- 工具不读取 `.env`，不使用现有 `DATABASE_URL`，拒绝生产模式、非回环数据库主机和未以 `_test` 结尾的管理库。它只创建、迁移和删除本次随机生成的 `drive_benchmark_<随机值>_test` 数据库。
- 文件存于本次创建的 OS 临时目录，带随机所有权标记。清理前校验真实路径、父目录、标记、文件类型与文件名；采用 `unlink`/`rmdir` 逐项清理，不递归删除输入路径。
- HTTP 服务仅监听 `127.0.0.1` 的随机端口。上传将请求流转为带 `duplex: half` 的 `Request`，直接执行真实 `DriveStore.writePart`；下载直接执行 `DriveStore.download`。
- 每个上传 worker 最多保留一片生成数据。片内复用随机 64 KiB 种子，并在每片写入不同序号；既避免全文件分配，也避免所有片完全相同掩盖顺序错误。上传后检查持久化分片 SHA-256，再对两条下载路径逐片流式计算 SHA-256。
- 控制组读取同一个已上传文件，以相同分片、并发、HTTP Range、客户端校验及 256 KiB 服务端读取缓冲，通过 `fs.createReadStream` 直接发送，绕过云盘数据库查询。
- 完成后关闭连接和监听器，等待测试数据库连接退出后删除测试库；只有数据库与临时文件均清理成功才输出成功报告。不增加生产启动命令。

## 测量结果

| 阶段 | 耗时 | 平均持续吞吐 | 阶段开始 RSS | 采样 RSS 峰值 |
| --- | ---: | ---: | ---: | ---: |
| HTTP 分片上传、持久化并完成 | 2.551 s | 200.71 MiB/s | 202.70 MiB | 333.90 MiB |
| DriveStore HTTP Range 下载并校验 | 1.971 s | 259.72 MiB/s | 257.50 MiB | 279.10 MiB |
| 直接 fs HTTP Range 控制组并校验 | 1.425 s | 359.33 MiB/s | 243.86 MiB | 250.49 MiB |

上传期间客户端生成数据的在用上限为 4 × 16 MiB，另有 64 KiB 种子；没有整文件缓冲。表中的 RSS **包含同一个 Node 进程中的 HTTP 客户端、服务端、依赖、流缓冲和分配器保留页**，不等于单独服务端内存，也不包含独立 PostgreSQL 进程或 OS 文件页缓存。采样可能遗漏短暂峰值，不能将 333.90 MiB 当作部署内存上限。

真实执行结果：上传后的 32 条持久化分片校验值全部匹配；DriveStore 下载的 32 片全部通过 SHA-256；直接 fs 控制组的 32 片全部通过 SHA-256。两次下载各校验完整的 536,870,912 B。随机测试数据库已删除、临时文件已移除、回环监听器已关闭。命令退出码为 0。

32 片元数据与两条下载路径的全部 SHA-256 再次匹配，随机数据库、临时文件和监听器均清理，退出码 0。该复测仍是同机、未清空页缓存、客户端与服务端同进程的单次结果；两次测量间未控制系统负载，不能把数值变化归因于本次流转换改动。

脚本局部 ESLint 与全项目 TypeScript 检查通过。未设置依赖本机性能的吞吐门槛；本次验收依据为真实持久化、完整字节校验、有界数据生成与流式消费，以及隔离资源清理。

## 结果边界

本次顺序为上传 → DriveStore 下载 → 直接 fs 控制组；未控制冷缓存，数据很可能命中本机页缓存。结果是单次测量，不能据此计算稳定分位数，也不能把控制组差值归因于某个单一组件。

此工具未经过 Next.js 路由、身份验证、Caddy、TLS、浏览器文件 API 或公网链路。Node 客户端下载只校验流中的数据，不另写一份目标文件。浏览器写盘、手机网络、代理与真实服务器磁盘仍须单独验证；不得把同机回环吞吐表述为“跑满用户带宽”。目标 Node 24、生产 Linux、实际域名与服务器链路不包含在本次结果内。

实现依据：[Node 流与背压](https://nodejs.org/docs/latest-v22.x/api/stream.html)、[Node 进程内存统计](https://nodejs.org/docs/latest-v22.x/api/process.html#processmemoryusage)。
