# 破碎的像素地牢浏览器验收

后续 0.3.1 的同层地图覆盖问题、根因与前后对照另见 [渲染修复验证](game-rendering-fix-validation.md)。下文保留 0.3.0 的验收范围与结果。

日期：2026-11-06。使用隔离测试数据库与合成成员账号，在本机 Windows / Chrome 155 中运行实际 TeaVM 游戏产物；浏览器由 Playwright 驱动，软件 WebGL 使用 SwiftShader。上游固定提交 `ce39efde1c4e9929103a1df684d94fab6aa84bed`，游戏显示版本 `3.3.8-WEB`。最后一轮真实双页回归使用本机 Next.js 生产构建和 Caddy HTTPS 入口 `https://127.0.0.1:3443`；游戏源码摘要为 `deb8312ce0f15c7f8263b712510ac94221f3cd1d033d2488c118cab2eff6406f`。本记录不代表用户服务器部署或所有实体手机已经验收。

## 验收范围

覆盖游戏目录入口、独立游戏页、原作角色创建、移动、战斗、账号保存、关闭后恢复、同步失败、备份、网页控件、键盘焦点与手机触摸。基础流程和双页存档冲突来自真实游戏，未用合成快照代替可玩角色。下文单独标明异常响应夹具与最终样式回放，不把这些模拟结果当成真实服务器或游戏玩法完成。游戏的全部角色、物品、楼层、结局与所有浏览器兼容性不在本次基础流程覆盖范围。

## 已观察的基础流程

- 桌面 `1440 × 900`：进入地牢、创建战士；浏览器进程关闭后重新登录，选择云端已有战士并继续同一层地图。真实服务端快照包含 `game1/game.dat`、`game1/depth1.dat` 和全局日志文件。
- 使用方向键与点击地图移动、穿过房间门、攻击并击败啮齿小鼠。游戏画面显示击败记录，随后原生存档的战士经验为 `1`、生命为 `20`。点击“同步进度”后页面显示账号同步成功。
- 没有既有语言选择的账号自动采用原作简体中文；云端偏好中实际保存 `settings.xml:languages = zh`。已有选择由原作继续使用。
- 人为断开测试浏览器网络，移动并同步后出现明确的红色“进度尚未同步”提示。离线点击“下载进度备份”得到含 5 个原生文件条目的 JSON；恢复网络后点击同步成功，错误提示消失。
- 打开“说明”能看到操作、账号存档、冲突、备份用途、作者及 GPL 署名，并提供对应源码下载与许可证链接。全屏按钮成功进入浏览器全屏；自动化环境中的浏览器退出快捷键不作为实体浏览器验证结论。
- Tab 可从游戏画布离开并依次到达“小工具”“同步进度”“全屏”“说明”，没有画布键盘陷阱；点击“小工具”完成同步后返回目录。
- 手机模拟 `390 × 844`：使用触摸进入存档选择、确认原角色的 `1/10` 经验并继续。网页文档为 `390 × 844`，画布从 y=129 延伸至 y=844，工具栏、同步状态、游戏顶部状态与底部操作区均可见，没有横向页面溢出。

## 旋转回合问题与修正

移动动画中点击同步并立即旋转时，最初发现回合一直无法完成，网页拒绝把旧检查点称为当前保存。源码检查表明上游 `Game.resize` 立即重建场景，Web `GameScene.destroy` 又不阻塞等待旧 actor 线程；动作尚在异步进行时重建场景可能使后续回合停止。

本站只在 Web 子类增加尺寸暂存：保留最近的正尺寸，等待活着的英雄回到可行动状态后调用原来的 resize 路径；非游戏场景与死亡后的界面不等待，冲突暂停的运行保持原场景。完整原作保存逻辑、场景布局与游戏内容均保留。

修正后实测：触摸相邻格移动，立即点击同步并从 `390 × 844` 切换到 `844 × 390`，同步完成；再次移动并切回竖屏，同步继续成功。离线提示条出现、恢复网络后提示条消失引起的画布高度变化也未阻断下一次移动与同步；最后通过“小工具”按钮保存并离开。横屏状态区和底部原生操作区完整可见。

## 双页并发与会话失效

- 在最终桥接源码对应的生产构建中，新建两个已登录标签页。两页均进入真实游戏菜单后，服务端版本仍为 `143`，没有 PUT 请求。该验证覆盖 PostgreSQL JSONB 改变偏好键顺序时，不把相同快照误判成新进度的问题。
- 第二页继续已有战士、移动并保存，观察到真实 PUT 200；第一旧页继续同一角色后观察到真实 PUT 409。旧页显示“存档版本冲突”，同步和全屏按钮禁用，游戏暂停。
- 冲突页点击“下载进度备份”成功下载含 5 个原生文件条目的 JSON。备份不作为服务端成功覆盖的证据；此前另一次冲突下载前后的服务端版本均为 `143`。
- 在同一浏览器上下文清除登录 cookie 后，正常游戏页与冲突暂停页均被身份检查转为“请重新登录”，两页 iframe 数量均为 0。随后该上下文的 IndexedDB 数据库列表为空，游戏设置前缀数量为 0。此次真实双页回归没有捕获到 `pageerror`。

## 手机冲突提示的生产样式复测

真实 409 揭示了生产样式加载顺序问题：Ant Design 后注入的 `.ant-alert` 将同特异度模块规则的 `display: grid` 覆盖成 `flex`，导致文字列宽度为 0。修正仅将局部选择器提升为 `.page .notice`，保留标准 Alert 与按钮，不使用全局覆盖或 `!important`。

修正后的 Next.js 生产构建已通过。新生产页面上的最终视觉检查回放前一步实际观察到的冲突状态；这张截图是布局夹具，不作为又一次真实 409 的证据。`390 × 844` 下实际计算结果为 `display: grid`，说明文字列宽 `308px`，提示区高度约 `171px`，两项操作均完整可见；文档尺寸仍为 `390 × 844`，iframe 从 y≈348 延伸到 y=844，没有页面横向溢出或提示文字被挤成单字列。

## 加载和异常响应夹具

- 在隔离浏览器上下文拦截游戏脚本，并推进该上下文的测试时钟至 181 秒，观察到“游戏尚未载入”和“尚未就绪”说明，同步禁用、重新载入可用。没有加速真实游玩的上下文，也没有把等待提示当作资源已加载。
- 将初始化 GET 的响应分别替换为 JSON `null` 和 `[]`，游戏引擎脚本没有启动，页面显示格式错误。最终桥接握手修复后，`[]` 在新载入页面中也会立即显示外层错误与重新载入入口；移除拦截并点击重新载入后，已观察到实际游戏就绪和同步按钮恢复。
- `tests/game-lifecycle.test.ts` 通过执行真实桥接模块验证延迟回复不能解除终止状态、冲突后仍检查身份、晚安装的父页面监听器可取得当前状态，以及 401/403 的空值或数组响应仍按身份失效处理。`tests/game-bridge.test.ts` 验证偏好及文件顺序不影响快照比较。这些模块测试不替代上述真实浏览器流程。

## 验收边界

手机测试使用触摸和视口模拟，未在实体 iPhone、Android 或 Safari 中执行；全屏退出快捷键、完整通关、全部角色及物品仍需分别验收。开发 HTTP 服务曾出现资源请求长时间等待，生产 HTTPS 入口能够加载真实游戏；本次没有给出跨设备加载耗时保证。最后一次仅为 CSS 复测重新启动的双页中，一页继续角色时停留在黑色原生过场，另一页正常持续保存，因此最终 CSS 截图使用明确标记的状态回放，未把该次旧页过场计为成功继续游戏。
