# 0.3.0 小工具与受管账号页面验收

日期：2026-11-06。范围为小工具目录、网站导航、用户名登录、账号管理、登录记录及成员设置；游戏画布与存档验收另行记录。运行环境为本机隔离测试数据库、`http://127.0.0.1:3001` 的 Next.js 开发服务及浏览器；全部身份和内容为合成测试资料。截图对应 `codex/feat/tools-member-isolation` 分支以 `aad65c4b53e1bf779711a66727ec303e419c11ed` 为基线的 0.3.0 工作树，随本次变更一并归档，不是另一台 Windows 服务器的运行证据。

## 视觉依据

[用户提供的布局示意](images/tools/layout-reference.png) 是 1071×700 图片：保留左侧导航，在内容区使用可进入的工具卡片。[同尺寸实现](images/tools/tools-reference-1071.jpg) 延续已确认的浅色网站外壳与 Ant Design；当前只有一个真实工具，不为示意图中的其他方框制造无功能入口。游戏图标直接保留指定上游资源，来源和许可见 [开发说明](../development/shattered-pixel-dungeon.md)。

新增卡片、账号行、表单与登录记录使用现有主题、文字层级、间距和 Ant Design 控件。工具卡片整体为链接，标题、描述和“进入工具”动作清楚可见；手机改为单列，主账号可从导航抽屉与“更多”菜单进入管理功能。原有四项手机底栏继续保留。

宽屏复核发现新增页面最初跟随现有外壳拉宽，因此为 `.tools-panel` 和 `.accounts-panel` 增加 1440 px 上限。最终 1920×1080 实测两页正文均为 1440 px，工具卡片宽 464 px，文档无横向溢出；外层 `.app-main` 仍为 1672 px。此局部约束保持原资讯页面布局。720×450 检查的是 1440×900 一半有效视口下的重排代理，不是浏览器实际 200% 缩放，更不是仅放大文字 200%。

## 真实操作结果

- 主账号以 `admin` 登录，完成首次验证器绑定及再次登录的 TOTP 验证；成员以分配的用户名和密码直接登录，没有强制验证器步骤。
- 主账号实际创建合成成员、修改显示名称、停用和重新启用、重置密码、撤销登录。停用和撤销操作有范围明确的确认文案，普通取消不提交。
- 重复用户名返回 HTTP 409 后显示可读错误，保留已填内容；修改表单未保存时关闭会询问是否放弃，继续编辑保留输入。
- 登录记录实际显示密码及验证器步骤的成功/失败，网络地址以脱敏前缀展示；按账号筛选后能查看对应记录。未用历史样例补造登录记录。
- 成员侧不出现账号管理入口，直接访问 `?view=accounts` 回到首页；切换账号后原搜索状态不会带给另一账号，成员设置使用用户名，不显示内部认证邮箱。
- 768 宽度从“小工具”导航按钮连续 Tab，经账号管理、用户菜单、搜索框到工具卡片；卡片有可见蓝色焦点，Enter 进入真实游戏页面，小工具返回按钮能回到目录。此项仅证明入口连通，不替代游戏玩法验收。
- “修改名称”弹窗用键盘打开后焦点位于关闭按钮，Tab 可到输入框、取消和保存并返回弹窗；Escape 关闭后焦点归还原“修改名称”按钮。

## 问题、修正与检查

| 发现 | 修正 | 验证 |
| --- | --- | --- |
| 减少动态效果时，Ant Design 下拉菜单因全局 `transition-duration: 0.01ms` 停在屏幕外 | 与主题的减少动效策略一致，将过渡设为 `0ms` | 320 宽度“更多”菜单可见，账号管理/设置等入口可点击；保留修后截图 |
| 登录页页脚文字对比度为 4.24:1，不足普通文字 4.5:1 | 使用既有 `textSecondary` 语义颜色 | 桌面和手机登录复扫该项不再违规；该组合已有 token 对比度检查 |
| 登录品牌链接朗读名称未包含可见副标题 | 移除覆盖可见文本的 `aria-label`，由完整品牌文字自然形成可访问名称 | 桌面和手机登录复扫该项不再违规 |
| 工具卡片链接名称覆盖了卡片内的部分可见文字 | 使用卡片可见标题、描述与入口文字形成自然名称，移除重复描述关联 | 桌面与手机工具目录复扫该项不再违规 |
| 密码显隐操作只有 14×14 px | 统一扩展为 44×44 px，并增加键盘焦点描边；密码输入外框取消纵向内边距以容纳目标 | 登录和成员密码表单复扫无目标尺寸违规；Tab 可达、实际点击显隐正常，目标实测 44×44 px |
| 宽屏新页面正文超过 1440 px | 仅新增工具和账号面板设置正文上限 | 1920×1080 实测两页正文均为 1440 px |

本轮 UI 静态验证：`npm run check:repo`、`npm run lint` 与 `npm run typecheck` 在上述修正后均退出 0；规范检查包含 34 组 token 对比度。整体测试、生产构建、数据隔离与迁移结果统一见 [0.3.0 验证记录](v0.3-validation.md)，不以 UI 检查代替服务端授权证明。

独立 Chromium 155.0.8059.86 使用 axe-core 4.14.0，启用 `wcag2a`、`wcag2aa`、`wcag21a`、`wcag21aa`、`wcag22aa` 标签。最终 [机器可读结果](tools-axe-results.json) 包含 13 个页面状态，均为 0 项 violation；11 个状态没有 incomplete，手机创建成员的正常和必填错误状态各留下同一用户名说明的 1 项对比度 incomplete。各状态通过的规则数在 25–31 项之间，不能相加当成独立合规准则数量。

未决项 `#username_extra` 已人工复核：提示框位于弹窗内，正常态矩形为 x=32、y=234、326×44，五个采样点的顶层元素均为提示本身；错误态同样无覆盖。[正常截图](images/tools/axe-mobile-create-member-final.png) 与 [错误截图](images/tools/axe-mobile-create-member-errors-final.png) 没有导航遮挡或裁字。实际文字为 `#595959`，透明背景继承弹窗白底，计算对比度 7.00:1。人工观察通过不改写 axe 的未决状态，也不据此宣称完整 WCAG 认证。

## 验证边界

本轮未完成 NVDA/VoiceOver 全流程、实体手机触屏和软键盘、仅放大文字 200%、所有浏览器兼容性或所有异常网络状态的人工验收。手机截图与触控尺寸来自桌面浏览器的响应式视口。游戏完整操作、持续游玩、账号云存档及生产部署必须分别使用对应证据，不能从工具卡片和登录截图推断通过。
