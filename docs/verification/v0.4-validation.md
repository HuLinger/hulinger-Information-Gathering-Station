## 应用、权限与持久化

- `npm run check`：显式启用隔离 PostgreSQL 与本机 Caddy，117 项中 109 通过、0 失败、8 项因 Windows 平台跳过；Linux 脚本由 CI 验证，跳过不记为通过。
- 转换数据库集成验证包括账号 RLS、复合外键、上传/任务/输出归属、幂等上传、配额、取消、失败/中断恢复、缺失结果、到期清理及停用账号清理。此组使用模拟 provider 验证任务机制，不等同于真实格式转换。
- 登录集成测试使用真实 cookie 与 PostgreSQL，覆盖未登录、成员、主账号、跨账号读取/上传/任务/下载/删除以及会话失效；服务端授权生效。
- 10 个并发停滞上传中 4 个获准、6 个及时返回繁忙，普通数据库读取继续；终止持锁数据库连接后上传明确中断，可重新尝试。中断 worker 会清除部分结果，不发布假成功。
- 最终上传确认增加独立竞态回归：阻塞最终状态更新，再终止上传锁连接。修复前复现误报 `ready`；修复后同一持锁连接内完成账号事务，返回 `UPLOAD_INTERRUPTED`，记录仍可重试。修复后的完整 `npm run check` 仍为 109 通过、0 失败、8 项平台跳过，生产构建亦重新通过。
- `npm run build`：生产构建与独立产物检查通过。修复 Windows 文件追踪误收运行期文件的问题；产物无私有运行目录、真实环境文件，原云盘文件保持不变。
- Windows 更新脚本在 PowerShell 7、Windows PowerShell 5.1 下分别 8/8 通过。测试使用隔离 Git 仓库和确定性 npm 夹具，不代替真实服务器切换。
- Gitleaks v8.30.1：包含实现提交 `edade181` 的 18 个提交历史扫描未发现密钥。固定来源清单中的公共 SHA-256 被误认成 key，新增豁免要求精确路径、文件名及完整摘要；[负例验证](conversion-gitleaks-validation.json) 确认更换值或同文件其他凭据仍被检出。
- `npm audit --omit=dev`：生产依赖 0 个已知漏洞。第一次网络请求失败未计为通过，恢复直连后重新取得完整审计结果。

## 真实引擎

各引擎的固定来源、镜像/JAR 摘要和许可见 [上游清单](../../integrations/conversion/UPSTREAM.json)。协议测试与真实 ConvertX 验证另见 [provider 验证](conversion-provider-validation.md)。

| 引擎与实际运行环境 | 样例及结果 |
| --- | --- |
| ConvertX 固定官方 Linux 容器 | BMP→PNG，解码后 2×2 RGB 像素完全一致；中文结果名保留；损坏输入明确失败 |
| Transmute 固定官方 Linux 容器 | 真实 bootstrap/API key 初始化；BMP→PNG 像素完全一致；损坏输入明确失败 |
| Stirling 核心 Linux 容器 | PNG→PDF、中文 PDF→UTF-8 文本、PDF→图片 ZIP；独立双页中文 DOCX→PDF→TXT/2 页 PNG ZIP 和 PDF→DOCX 均保留预期中文 |
| NCM Windows .NET 10.0.403 网关及标准 Linux 容器 | 两个环境的实际 LibNCM 均对独立合成 NCM 提取 MP3 与 FLAC，输出与原始字节完全一致；损坏输入明确失败；网站下载 FLAC 同样逐字节一致 |

统一真实测试命令为 `npx tsx scripts/verify-conversion-engines.ts`，可显式选择引擎；没有用模拟 provider 代替缺失引擎。本地最终四容器通过临时 HAProxy 的仅回环端口完成整组真实测试。NCM 页面最先使用本机真实 .NET 服务验证；Linux 容器随后独立验证为 UID 1654、只读、移除全部能力、禁止提权、无宿主端口绑定。

首轮 CI 的正式网关启动失败，保留该失败记录。固定 Caddy 2.11.7 二进制带 `cap_net_bind_service=ep` 文件能力；同样文件能力、非 root、只读、`cap_drop: ALL`、`no-new-privileges` 的 Linux 复现实验被拒绝执行，移除该文件能力后同一实验退出 0。派生网关仅移除这项不需要的文件能力，不增加运行权限。

修复后提交 `a093628` 的 [CI 运行](https://github.com/HuLinger/hulinger-Information-Gathering-Station/actions/runs/42233249659) 三项全部通过：Repository baseline、Windows update safety、Conversion engines。引擎检查使用正式 Caddy 网关和四个真实容器，首次转换全通过；随后重启全部服务、再次初始化并比较凭据文件完全一致，再跑整组转换仍通过。该运行不代表后续上传竞态修复或证据提交的 CI 结果；最终合并依据见 [PR #5 的检查状态](https://github.com/HuLinger/hulinger-Information-Gathering-Station/pull/5/checks)。

## 页面证据

使用生产 Next 构建、本机 HTTPS Caddy 和隔离成员账号。已完成：

- 小工具卡片导航、真实不可用引擎提示、空列表、说明弹窗的 Enter/Escape 操作与关闭后焦点恢复。
- 通过键盘选择目标和引擎并提交；图片先用 ConvertX 再用 Transmute，共 1 次上传 PUT、1 个源文件、同一 uploadId 的 2 个成功任务。下载后核对 PNG 解码像素，刷新仍显示任务。
- 手机上传损坏 BMP 后明确失败；复用源文件换引擎创建任务，暂停隔离 worker 后通过 UI 取消排队。清理弹窗说明关联范围，Escape 取消并归还焦点，确认后只清理对应源文件及关联任务。
- 手机真实 PDF→TXT 并下载，中文文本完全保留；NCM 页面自动显示“原始音频（MP3 / FLAC）”，输出下载为原有 FLAC，而非错误标为 MP3。
- 模拟浏览器上传网络中断后保留当前文件和重试入口；刷新显示真实未完成上传记录，能单独清理。这里仅网络中断由路由故障注入，后台记录与清理为真实接口。
- 长中文文件名在 320 CSS px 和 200% 文字测试中可折行，没有横向溢出。
- 清除隔离浏览器会话后刷新受保护页面，实际跳转到登录页并显示登录表单；不向未登录请求显示转换内容。
