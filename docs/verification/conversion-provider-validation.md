## ConvertX 真实文件实测

本地 Windows 的 Docker Desktop / Linux 容器运行未修改的官方 ConvertX v0.20.0。镜像索引为 `sha256:6259e0c1e063120b1ddbc6937372a83be58182b2c9dc82264f58e100907b3e51`，linux/amd64 清单为 `sha256:bba2e672eb9a42ac9d879a7758b946163f9eae00c3abd93155d0f597635970c2`。下载时对官方清单、配置、层及证明元数据逐项核对 SHA-256；导入后 Docker 报告的仓库摘要仍为该固定索引。

引擎按集成 Compose 的非 root 用户、只读根目录、移除 capabilities、临时文件系统和内部网络配置启动；实际 `/healthcheck` 返回正常。独立实测通过临时 HAProxy 将 `127.0.0.1:18091` 转发到该容器，不占用正式网关端口，也不修改引擎配置。该通路只用于开发验证，不能据此宣称正式 Caddy 网关已验证。

## 上游清理的实际边界

首次独立成功及失败测试前，容器中已有探测会话留下的 1 个空任务、0 条文件记录和 0 个上传/输出文件。测试后，任务数回到该基线，上传/输出文件数仍为 0；两个测试任务已由上游删除接口移除。

ConvertX v0.20.0 的删除接口仍留下两条 `file_names` 状态记录，分别对应成功和失败任务。记录中的名称为本站发送的固定 `input.bmp` / `input.png`，不含用户的中文原文件名或文件内容。因此，本次验证只证明任务与文件内容被清理，不能表述为所有上游元数据即时删除。该 SQLite 数据库位于容器临时文件系统，重建引擎会清除这些临时记录。

本次样例不足以证明所有图片、文档或音视频格式均能转换；上游没有提供安全取消语义的运行任务，仍按隔离临时空间及上游到期策略处理。整站账号隔离、24 小时保留、恢复、手机与键盘体验应以对应整体验收为准。
