# 0.2.0 云盘与更新流程验证

日期：2026-11-04。范围：[ADR 0005](../adr/0005-large-file-drive.md) 的私有大文件云盘和保留服务器定制的更新。测试只使用合成文件与独立测试数据库；本次未连接或更改用户服务器。

## 本地检查

- Windows 11、Node.js 22.14.0、PostgreSQL 18.6；设置显式测试库、测试认证参数与 Caddy 2.11.7 可执行文件后，`npm run check` 通过规范、ESLint、类型与测试：70 项，62 通过、0 失败、8 跳过。
- 跳过为 Linux 更新/备份 4 项、未启用的外网采集 2 项、Windows 不允许创建文件符号链接的负例 1 项，以及 POSIX 只读权限用例 1 项；目录 junction 负例实际通过。Linux 用例及符号链接负例由 Linux CI 再验证，不把 skip 计作通过。
- `npm run build` 完成生产构建，包含云盘列表、上传、完成、文件操作、授权与下载路由。`npm audit --omit=dev` 返回 0 项已知漏洞。开发依赖基线风险见 [首版记录](v1-validation.md)，此次未升级依赖。
- Windows 更新工具真实 Git 夹具：PowerShell 7 与 Windows PowerShell 5.1 各 8 项通过，验证两笔本地提交保留、合并冲突、源目录和私有配置不变、校验失败、脏工作区、已有/嵌套目录和 junction 拒绝。测试 npm 为确定性夹具；目标候选自己的安装与构建仍须实际执行。

## 数据与权限

- PostgreSQL/磁盘集成验证乱序并发、重复分片、重新创建存储实例后续传、截断/过长/校验失败/流中断、空文件、容量竞争、完成与取消竞争、回收站恢复、过期清理及孤儿对象。
- 真实身份库和隔离数据库验证匿名拒绝、非拥有者拒绝、MFA 前后权限、撤销会话，以及云盘读写 Origin 校验。
- Range/If-Range、HEAD、416、私有下载头和字节完整性经过应用路径与真实 Caddy 夹具验证；Caddy 丢弃客户端伪造文件定位头。真实登录后经过容器/Caddy 的完整 HTTP 链路等待本次 CI 证据。
- 恢复校验器实测接受完整配对文件，并拒绝缺失分片、错误大小和内容损坏。完整 restic 加密备份、恢复、运行角色与重启验证等待本次 CI 证据。
- NTFS 预分配实测回归：64 MiB 的暂存文件已消耗实际磁盘空间时，不再次扣除同一空间；稀疏文件仍预留未来写入空间。就绪检查使用真实读写/删除探针，避免 Windows `fs.access` 未检查 ACL 而误报可用；成功结果缓存 60 秒。
- 迁移 `004-drive.sql` 只新增云盘表和索引，不改既有身份与资讯结构；运行角色新增对应表权限。回退旧应用前保留新文件和表，数据库恢复必须与文件恢复来自同一备份点。

## 大文件性能

512 MiB、32 个 16 MiB 分片、4 路并发的本机 HTTP 基准完成上传及双路径下载，全部 SHA-256 匹配：上传 200.71 MiB/s、应用存储 Range 下载 259.72 MiB/s、直接文件流控制组 359.33 MiB/s。客户端与服务端同一个 Node 进程，峰值 RSS 333.90 MiB；该数据不是服务端单独内存。

完整环境、命令和限制见 [基准记录](drive-benchmark.md)。它未经过 Next.js、Caddy、TLS、Cloudflare Tunnel 或公网，不能推导用户最大网速；部署后须沿实际线路验证，按瓶颈调整并发。
