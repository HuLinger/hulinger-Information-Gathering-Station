# ADR 0007：账号独立的中文格式转换工具

- 日期：2026-11-06
- 状态：已决定，按用户本次功能授权实施；验收与服务器部署另行记录

## 背景

用户要求下一个版本在“小工具”新增格式转换卡片，选用 ConvertX、Transmute、Stirling-PDF 及 ncmdump-net；统一中文并使合适工具之间切换顺畅。用户已确认另一台 Windows 服务器可以使用 Docker／WSL2，转换文件默认保留 24 小时。本源码电脑不等于目标服务器。

## 决定

保留 Next.js、Ant Design、PostgreSQL 和现有 Windows 服务。新增单一“格式转换”页面，完成选择文件、目标格式、推荐或手动引擎、上传、后台转换、下载、换引擎重试与清理的闭环。切换引擎复用本站已有上传，不要求用户重新上传。格式和引擎以实际适配能力为准；失败、未部署和不支持状态明确显示。

服务器通过独立 Linux 容器运行以下固定上游，网站仅通过服务端适配器调用，不把上游会话、API 密钥或原始下载地址发给浏览器：

| 引擎 | 固定依据 | 接入方式 |
| --- | --- | --- |
| ConvertX | `C4illin/ConvertX` v0.20.0，`42224e3f1f1ad0eb6e6d2bac661a5b3f2b2a2976`，AGPL v3 | 未修改的官方镜像；服务器适配其网页协议，每次转换独立上游任务与会话 |
| Transmute | `transmute-app/transmute` v2.1.1，`7de1265fbfbbfd073c5c9a65ed1f7e45bc3ca50c`，MIT | 官方 REST API；使用单独的内部服务账号/API 密钥，本站保持每个用户的权限边界 |
| Stirling-PDF | `Stirling-Tools/Stirling-PDF` v3.3.0，`7825214811d98fd3ec260bf315cd998ecb73b36b` | 官方纯核心、API-only server JAR；使用 MIT 核心模块，不依赖商业模块或云端账号 |
| ncmdump-net | `xiSage/ncmdump-net` v2.0.1，`8ccdd3534d5006d3f604d3790ada8778e8973e6f`，MIT | 小型内部 HTTP 包装调用 LibNCM；关闭外部封面抓取，只接收用户上传的 NCM 文件并返回原始音频 |

## 权限与文件生命周期

- 上传、任务、输出的服务端记录均绑定当前账号，使用账号复合外键及 PostgreSQL RLS；主账号也不越过业务账号边界。未登录、停用、会话撤销、跨账号访问均拒绝。
- 源文件和结果保存在独立临时目录，不存入 public，不复用用户文件名作为磁盘路径。上传与下载有界流式传输，限制文件大小、待处理数、输出总量、执行时间和存储余量。
- 后台任务在关闭页面后继续。状态明确区分排队、处理中、成功、失败和取消，不伪造引擎没有提供的百分比。只有结果实际写入并验证后才能报告成功。
- 完成后的结果和可重试源文件保留 24 小时；未完成上传及失败任务同样有到期时间。后台定时清理，手动删除只作用于本人的非运行任务。运行任务不承诺上游不支持的即时取消。
- 转换目录属于可丢弃临时数据，不加入长期业务备份；数据库恢复后核对输出是否存在，不能提供已丢失结果的假下载。重试需要原输入仍存在。云盘原文件与游戏存档不受影响。

## 部署、维护与成本

四个引擎不发布宿主端口，只加入独立的 `internal: true` 转换网络，不挂载业务数据库、云盘、密钥或宿主目录。Windows 宿主通过单独的 Caddy 网关访问四个固定上游；只有网关同时加入普通接入网络，并将 `8091` 至 `8094` 绑定到 `127.0.0.1`。这是为兼容 Docker 对纯内部网络的端口发布限制，不能通过关闭内部网络隔离来解决。网关关闭管理 API 和自动 HTTPS，以非 root、只读根目录运行，不接受动态代理目标。Docker 主站和 worker 仍通过转换网络的服务 DNS 直接访问引擎。引擎运行期不需要公网，禁用 NCM 外部封面请求。镜像、JAR 和源码锁定版本与摘要，提供许可证与对应上游源码链接。新增适配代码和维护脚本留在本仓库。

网关派生镜像移除 Caddy 二进制的特权端口文件能力，二进制内容不变。本网关只用 8090–8094，继续以 `cap_drop: ALL` 与 `no-new-privileges` 运行；此适配避免 Linux 拒绝执行带 effective 文件能力的程序，不增加运行时权限。

图片、文档、PDF 和音视频转换消耗 CPU、内存及临时磁盘；默认单任务执行，配置明确上限，增加并发前实测目标机器。容器磁盘和内存仍由目标 Windows／WSL2 配置决定，不能用本机结果保证公网速度或所有格式。无需购买云转换服务；成本来自用户自己的硬件、电力与存储，不虚构未知机器的费用金额。

新增数据库迁移只增加转换表。0.3.1 升级先备份并构建候选；回退应用时停止转换 worker 和引擎、保留既有业务表，转换临时数据可按到期清理。禁止改写已应用迁移或修改原 Windows 服务的身份配置。引擎版本更新先审查 API、许可、格式能力与真实文件回归，再更改固定摘要。

## 备选方案

直接 iframe 四个原生页面会暴露不一致的登录、英文文案与文件历史，难以保证本网站的账号边界，因此采用统一界面与内部调用。全部原生安装在 Windows 上需要维护大量格式依赖且 ConvertX 官方不提供等价 Windows 发行；按用户选择采用 Docker／WSL2。将全部转换代码并入 Next.js 会扩大网站进程的依赖与资源风险，因此转换放在受限容器中。

## 验收

各引擎至少一条真实上传、转换、下载和输出内容验证；中文文件名与中文文档；多账号越权负例；超限、缺少引擎、错误文件、超时和任务中断；刷新恢复状态；保留期与清理；桌面、手机和键盘流程；Linux 与 Windows 候选更新。所有模拟故障与未覆盖格式单独标明，不把上游支持数量当作本站已验证数量。
