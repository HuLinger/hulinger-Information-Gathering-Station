# ADR 0002：首版聚焦自动汇总 AI 资讯

- 日期：2026-11-04
- 状态：用户已确认产品方向；详细设计参数为首版默认，待设计收敛
- 关联：[ADR 0001](0001-project-baseline.md)、[首版产品设计](../design/v1-product-design.md)

## 背景

原始基线按通用个人资料收藏设计，以手动保存为主，将 RSS 和自动采集列为后续。用户本轮明确：首版用于收集整理网络 AI 相关信息，重点包括模型更新与 GitHub 有趣热门项目；自动收集并汇总到站内，支持人工修正；电脑和手机适配；本轮只做设计。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 手动收藏为主 | 开发和来源维护较少，但发现新信息仍依赖本人逐站查找 |
| 自动收集、逐条人工确认后入站 | 编辑控制最强，但每天存在整理积压；用户未选择此流程 |
| 自动收集并入站，保留人工修正 | 持续发现和阅读成本较低，需要可信来源、去重、核对异常和可解释时效 |

## 决定

采用用户选择的第三种方案。正常有效条目自动进入私有信息流，异常进入需核对；按模型、项目与工具生态整理内容，保留来源。定时采集公开白名单来源进入首版范围，解除 ADR 0001 对应初始章程中“RSS/自动采集后续再评估”的范围假设，但不解除来源安全门禁。

保留单人私有、Ant Design、Git 分支管理和上线标准。采用同一响应式网站覆盖电脑和手机，不引入原生 App 作为首版依赖。具体同步周期、来源规模、页面和热度算法在设计稿中明确标为可调整默认。

## 影响与约束

- 自动采集、来源健康、去重及人工覆盖保护成为首版必需能力；来源全部失败不能呈现为“没有新资讯”。
- GitHub 自定义关注增长与官方 Trending 分开；历史不足不虚构变化，不承诺全网或全 GitHub 覆盖。
- 开启采集前必须满足已有 SSRF、限流、外部内容处理和访问边界；第三方内容不具有指令权限。
- 原始摘要与自动/人工生成内容分开标记。使用付费模型做中文摘要不作为自动采集运行的必要条件。
- 后续技术决策需同时考虑定时任务、存储、运行成本和恢复能力；本轮不选定供应商、不接入服务、不编写代码。

## 验证与后续

设计文档需覆盖来源 → 自动入站 → 双端阅读 → 人工整理 → 导出的完整流程；同步异常、重复、热度窗口和跨设备修改均有验收案例。实现后执行产品设计中的功能验收与既有上线门禁。ADR 0001 的其他原则继续有效。
