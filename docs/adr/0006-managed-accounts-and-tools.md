# ADR 0006：受主管理的账号、独立数据与小工具

- 日期：2026-11-06。
- 状态：采用，进入实现与验证。
- 需求依据：用户提供“小工具”卡片布局，指定接入 `glassesmonkey/shattered-pixel-dungeon-web`，要求二次开发、电脑/手机适配、admin 创建和管理成员、记录登录、成员密码登录免验证码。用户随后明确选择“所有功能，但每个账号的数据独立”。
- 版本：0.3.0。此次授权将既有单拥有者业务扩展为私有、邀请式的受管账号；仍不开放注册、匿名分享或公共社区。

## 身份与管理

站点主账号仍由 `app_settings.owner.id` 标识，`admin` 是其登录别名，不是客户端或任意用户名获得管理权限的依据。保留主账号 MFA、恢复及既有会话规则；新成员由主账号在已完成 MFA 的会话中创建，使用用户名和密码登录，不要求邮箱、验证码或 TOTP。禁止公开注册。主账号可停用/启用成员、重置成员密码、撤销成员会话；这些操作及成功/失败登录留有脱敏记录，默认保留 30 天。

账号管理仅主账号可用。其他业务在服务端按经过认证的稳定账号 ID 授权；禁用和密码重置撤销现有会话，不能只隐藏界面。

## 所有业务的数据隔离

资讯、实体关注、个人整理、来源配置与采集游标、修订/合并记录、导出、云盘、游戏存档均属于单个账号。新账号初始化为空，仅建立同一套关闭状态的来源预设，不继承主账号内容或文件。现存数据迁移到原主账号名下；无法确定旧数据所属主账号时停止迁移，不猜测归属。

资讯业务表增加账号列、账号内复合键和关联约束，并使用 PostgreSQL RLS；请求从已验证会话建立事务内账号上下文，缺失上下文拒绝业务读写。不同账号可有相同的来源/外部实体标识，不能因主键冲突覆盖彼此。云盘继续按现有 `owner_id` 校验所有文件操作，并限制容量展示和导出到本人数据。后台采集、清理、导出和持久队列任务均显式携带账号，不借用全局默认主账号。

连接池不得遗留上次请求的账号状态；使用事务内设置并在结束时清理。身份、主账号标识、站点健康等必要系统数据独立于业务上下文。跨账号 API、关联字段、导出和后台任务需真实数据库负例验证。

## 小工具与游戏

沿用既有 Ant Design 和设计令牌，增加“小工具”导航和响应式卡片网格。首张卡片进入独立游戏页面，手机使用可用视口和触摸操作，桌面支持键盘/鼠标；不展示假工具入口。

指定游戏为 GPL 的 Java/TeaVM Web 分支，固定上游提交并保留相应源码、许可、作者署名、构建脚本和本地改动说明。游戏保持独立构建模块；集成层处理站点登录、账号存档同步及页面适配，方便继续修改游戏源码和追踪上游。

游戏服务器存档以会话账号为键，客户端不能指定其他账号。启动前取得本人快照并初始化独立 IndexedDB 与偏好命名空间，保存采用版本比较拒绝过期覆盖；同步失败有可见状态，不把浏览器缓存当作服务器已保存。退出/切换账号后不得继续运行或提交旧会话游戏。游戏资源的 iframe/WebAssembly 必要策略只作用于游戏入口，其他页面的限制不放宽。

## 维护、备份与交付

继续采用现有 Next.js、PostgreSQL、独立 worker 和 Windows/Compose 交付。新增 Java 构建依赖只用于生成游戏产物，运行服务不要求额外 Java 进程；源码与产物对应明确上游版本和本地补丁。新增账号数据、登录记录和游戏存档纳入数据库备份，云盘文件仍配对备份。多账号迁移后不能直接回退到假定全库只有本人数据的旧应用；回退必须停止入口，按配对快照与已核验版本恢复。

本次只在本地与隔离 CI 验证并交付仓库，不直接操作用户另一台 Windows 服务器。该服务器的 `admin` 登录定制继续通过候选更新合并保留，并按实际服务配置验证升级。

## 验收

- 主账号创建/停用/重置成员、成员免验证码登录、主账号 MFA 和撤销会话、登录事件成功/失败区分。
- 至少两成员与原主账号跨资讯、配置、关联、文件、导出、后台采集及游戏快照的读写隔离。
- 旧主账号数据无损迁移、新装初始化、多次迁移幂等、备份恢复与不兼容回退说明。
- 游戏真实构建，创建角色、移动/战斗、保存、刷新恢复、不同账号切换及手机触控；云端保存冲突/失败处理。
- 小工具与管理页面的桌面/平板/手机/窄屏、键盘、对比度及关键错误状态截图。
