# UI 与交互规范

生效日期：2026-11-04。适用于全部页面、组件和后续改版。Ant Design 已由项目所有者确认；本文件定义验收要求，当前尚无已实现页面。

## 1. 采用一套设计体系

- 以 **Ant Design** 为唯一基础组件体系，优先复用其导航、表单、表格、弹窗和反馈组件，不混搭其他完整 UI 组件库。Ant Design 官方将其定位为面向企业产品的设计体系；本项目借用其一致性与复用能力。[官方介绍](https://ant.design/docs/spec/introduce/)
- 页面视觉服务于个人信息的收集、整理和查找：清晰的信息层级、稳定的操作位置、适度的信息密度。避免大面积装饰占据主工作区。
- 图标使用同一图标集及一致的线宽；关键动作有文字标签，纯图标按钮必须有可访问名称。
- 更换体系、增加组件库、修改全局 token，先记录原因与影响，再随变更一起评审和回归；不允许各页面自行发展一套样式。
- “采用 Ant Design”不代表获得任何厂商认证，也不代表自动满足可访问性。上线验收以真实页面和完整流程为准。

## 2. 统一设计变量

[design/tokens.json](../design/tokens.json) 是项目视觉变量的唯一基线。以下数值均为本项目选择，并非宣称是 Ant Design 的全部默认值或强制值。

| 项目 | 约束 |
| --- | --- |
| 间距 | 0、4、8、12、16、24、32、48、64 px；常规组件内 8–16 px，区域间 24–32 px |
| 字号 / 行高 | 辅助 12/20，正文 14/22，阅读正文 16/26，分区标题 20/28，页面标题 24/32 px |
| 字体 | 系统无衬线中文字体栈；正文不使用装饰字体；标题通常 600 字重 |
| 圆角 | 小 4、标准 6、大 8 px；不按页面任意变化 |
| 控件 | 默认高 40 px；桌面紧凑模式可用 32 px；触控目标至少 44×44 px |
| 色彩 | 使用 `primary`、`textPrimary`、`surface` 等语义名称，不在业务组件散落十六进制色值 |
| 边框 | `borderDecorative` 仅作装饰分隔；识别输入框等控件时使用 `borderInteractive` 或其他满足对比度的线索 |
| 动效 | 常规 120–200 ms；尊重减少动态效果设置，不用动画阻塞操作 |

实现时集中把这些变量映射到 Ant Design 主题配置，业务组件消费解析后的主题值。弹窗、通知与消息必须共享主题上下文；官方提示部分静态方法无法自动继承 `ConfigProvider`，应使用相应上下文方案。具体 API 按落地时锁定的版本验证。[官方主题文档](https://ant.design/docs/react/customize-theme/)

`contrastPairs` 定义可自动计算的颜色组合；其通过仅证明这些不透明色值组合，不覆盖浏览器实际渲染、透明度、背景图、所有组件状态或整个 AA 合规性。新增颜色组合时必须追加验证。

## 3. 布局与信息密度

- 桌面采用稳定的应用外壳：顶部工具区、左侧导航、内容主区；顶部基准 56 px，侧栏 232 px。主内容最大宽度 1440 px，长篇阅读区最大宽度 760 px。
- 以列表作为信息集合的默认视图；卡片用于封面或摘要具有识别价值的内容。日期、类型、标签使用稳定列位和统一格式，避免将所有信息同时强调。
- 一个页面一个主标题；每个操作区域最多一个主要按钮，其余按次要、链接、危险操作分级。删除动作不得与保存动作混淆。
- 默认舒适密度；紧凑模式只能由用户显式选择，并保留可访问的点击范围和可读文字。
- 长标题允许换行或截断后查看完整内容；长 URL、连续英文、多个标签不能撑破容器。数字列对齐，空值有明确一致的表达。

| 视口宽度（CSS px） | 项目响应式要求 |
| --- | --- |
| 小于 768 | 单列；侧栏改抽屉；左右边距 16；筛选可折叠；表单单列；触控目标至少 44×44 |
| 768–1023 | 导航可收起；主操作保持可见；次要信息移入详情 |
| 1024 及以上 | 可常驻侧栏；内容边距 24；表格保留明确列优先级 |
| 1440 及以上 | 内容遵守最大宽度，额外空间不拉长阅读行 |

这些是项目布局断点，不要求覆盖 Ant Design 内置栅格断点。移动端优先把信息行转为列表；确需二维表格时仅表格区域横向滚动，并提供可访问的区域名称和完整数据入口。

## 4. 核心任务的交互契约

| 场景 | 必须满足 |
| --- | --- |
| 收集信息 | 标题、来源、类型等字段有明确标签和示例；必填规则在提交前可见；重复收集提示已有条目并允许查看 |
| 搜索 | 明确搜索范围；支持 Enter 与清空；中文输入法组合输入期间不提前提交；较慢请求显示状态；旧响应不得覆盖新查询 |
| 筛选与排序 | 已选条件、结果数量和清除入口可见；返回列表保留位置与条件；含私人查询词的状态默认存会话，不能擅自写入可共享 URL 或遥测 |
| 信息详情 | 来源链接、收集时间、标签和编辑入口位置一致；外部链接可辨认；原内容不可用时保留本地元信息并说明原因 |
| 编辑与保存 | 字段错误就近显示并关联输入框；失败保留输入；保存过程中防止重复提交；离开未保存编辑时有保护 |
| 删除与恢复 | 普通删除进入可恢复流程；永久删除明确范围并二次确认；批量操作显示选中数量和作用范围 |
| 导入与导出 | 展示格式、进度、成功/失败数量和重试入口；部分失败不能只显示整体成功；大任务可在离开页面后查询结果 |

对当前版本尚不支持的功能不展示虚假可点击入口；实现时逐项验收。本表规定相应功能存在时的行为，不意味着首版必须同时包含全部能力。

## 5. 完整状态与反馈

每个数据页面和异步操作必须设计并实现适用状态：初始加载、正常、空数据、无搜索结果、提交中、成功、失败、会话失效、网络中断；组件还覆盖悬停、焦点、选中、禁用和校验错误。

- 初次加载使用有结构的占位；后台刷新保留已有内容，不让布局反复跳动。
- 空数据说明如何开始；无搜索结果显示当前条件和清除入口；两者不能共用含糊文案。
- 错误说明发生了什么、数据是否已保存、可采取的动作；技术错误码可供排查，不能替代可读说明，也不能暴露内部数据。
- 成功反馈轻量且可被辅助技术获知；重要失败留在页面可重试，不能只靠几秒后消失的提示。
- 禁用动作有可获得的原因，不能只依赖鼠标悬停提示。

## 6. 可访问性底线

目标为 **WCAG 2.2 AA**；以下为重点验收项，发布前仍须检查所有适用的 A 与 AA 成功准则。[WCAG 2.2 正式标准](https://www.w3.org/TR/WCAG22/)

- 普通文字与背景对比度至少 4.5:1；大字至少 3:1；不把辅助信息做成不可读的浅灰。大字判定遵循标准定义，不按项目标题名称判断。[1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- 识别控件与状态所必需的视觉线索和信息图形，与相邻颜色至少 3:1；颜色之外还需文字、图标或形状传递状态。[1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)
- 全流程可用键盘完成；焦点顺序符合阅读顺序、清晰可见。弹窗打开后合理安置焦点、限制在弹窗内、关闭后归还触发元素；无键盘陷阱。固定工具栏不能遮住焦点，项目要求焦点元素尽可能完整可见。[2.4.11](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)
- WCAG 2.2 AA 的目标尺寸基准为 24×24 CSS px，并含间距等例外；本项目把主要触控目标提高到 44×44 px。不能将 44×44 误称为 AA 的统一要求。[2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- 200% 文字缩放无内容丢失；在 320 CSS px 宽度或等效 400% 缩放下，普通内容无需双向滚动，二维数据表等标准允许的内容例外另行检查。[1.4.10](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)
- 使用语义化标题、导航、列表、表格和表单标签；图片有适当替代文本；提示与输入关联；动态结果可被辅助技术感知。登录允许密码管理器和粘贴，不把记忆或解谜作为唯一认证路径。

## 7. 主题策略

首版以亮色主题为发布要求。暗色 token 已预留，尚未实现或验收前不展示主题切换入口。启用暗色时，使用一致的语义映射并检查所有交互状态、浮层、通知和第三方内容；不得直接反转颜色。两套主题均要满足实际页面的对比度要求，主题偏好可以保存，但不能混入个人内容数据。

## 8. UI 验收与变更证据

每次新增或明显改变页面，应在 PR 中提供真实渲染截图和操作验证结果，使用虚构数据，遮蔽个人信息；截图记录视口、主题、页面状态和对应提交。

| 矩阵 | 验收内容 |
| --- | --- |
| 390×844、768×1024、1440×900 | 受影响页面的正常状态；导航、搜索、筛选和主操作可用，无意外溢出 |
| 320 CSS px 宽与 200% 文字缩放 | 内容重排、长标题、错误信息和表单；不得隐藏必要功能 |
| 1920×1080 | 应用外壳或布局改动时验证最大宽度和阅读行长 |
| 桌面与触屏各一次 | 加载、空数据、无结果、请求失败、保存失败、权限/会话失效等受影响状态 |
| 键盘与屏幕阅读器 | 完成登录、收集、查找、编辑、删除/恢复中受影响的完整路径 |
| 暗色（启用后） | 重复受影响页面与状态；包含所有浮层 |

合并前必须满足：使用统一组件和 token；视觉层级一致；状态完整；键盘可操作；实际对比度通过；自动可访问性检查无未处理问题；人工复核通过。自动扫描或截图对比不能替代人工任务验证。阻断问题包括主要操作不可达、内容丢失、个人数据暴露、错误状态误报成功，以及未满足适用的 A/AA 准则。
