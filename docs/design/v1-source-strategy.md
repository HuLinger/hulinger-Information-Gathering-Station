# 首版来源与自动汇总策略

日期：2026-11-04。状态：首版来源策略；采集器进入实现验证，生产来源默认关闭，须在部署环境验证后启用。关联：[首版产品设计](v1-product-design.md)。

用户已确认：首版聚合网络 AI 信息，重点是模型更新、GitHub 有趣热门项目；自动采集并直接进入站内，允许人工修正；电脑和手机都可使用。少量官方工具生态作为设计默认补充。本文的候选来源、数量上限和检查节奏是可调整的设计默认，不表示已开通服务或已完成采集。

## 1. 白名单与首版边界

- 仅接入经登记的公开来源；优先官方 RSS/Atom 或 API。网页变更采集必须逐源验证页面结构、时间提取、访问规则和失败检测后才启用。
- 白名单按具体入口及允许的目标路径登记；记录归属、内容范围、接入方式、启停状态和最近验证时间。不能仅凭域名相同就抓取整站。
- 首版信息范围为模型发布/更新/停用、明确的工具与 API 变更、AI 项目发现和已关注项目版本事件；公司招聘、融资、泛行业营销默认排除。
- 只对登记范围作汇总，不承诺全网覆盖、即时获知或完整 GitHub 排名；新增来源不自动获得“官方”身份。
- GitHub 以原始仓库及维护者发布为项目来源；项目作者自述和厂商公布的性能不等于经过独立验证。

## 2. 候选来源清单

| 候选入口 | 核验情况 | 首版用途与接入条件 |
| --- | --- | --- |
| [OpenAI News RSS](https://openai.com/news/rss.xml) | HTTP 200；可解析 RSS，含 GUID、发布时间与分类 | 产品/模型公告；过滤无关分类 |
| [OpenAI API 更新日志](https://developers.openai.com/api/docs/changelog) | 官方日期分组更新页 | API、模型与停用事件；网页适配验证后启用 |
| [Claude Platform RSS](https://platform.claude.com/docs/en/release-notes/feed.xml) | 官方更新页提供订阅入口；初次入口核验 200，应用直连实测返回地区 307 跳转，当前拒绝启用 | 可选来源；必须在目标服务器重新通过连接与解析验证，不能绕过跳转校验 |
| [Microsoft AI 官方订阅](https://blogs.microsoft.com/blog/tag/ai/feed/) | 应用安全网络链路实测 200，可解析 RSS | 首批稳定公告源；覆盖微软 AI 产品与生态动态，非具体模型事件按工具类收录 |
| [Anthropic News](https://www.anthropic.com/news) | 官方公告页 | 重大模型与工具公告；网页适配验证后启用 |
| [Gemini API 更新日志](https://aistudio.google.com/docs/changelog) | 官方日期分组更新页 | 模型、API、迁移及停用事件；网页适配验证后启用 |
| [GitHub Search](https://docs.github.com/en/rest/search/search) | 官方仓库搜索 API | 按 AI 主题、关键词和明确条件发现公开项目 |
| [GitHub Releases](https://docs.github.com/en/rest/releases/releases) | 官方版本发布 API | 已关注或已选入项目的版本事件；默认正式版本，显式选择后包含预发布 |

以上核验仅确认来源形式与入口，不是当前新闻真实性复核，也不是自动接入成功记录。首次配置只开启通过连接与解析验证的来源；未通过的来源显示“待配置”，不影响其他来源运行。

## 3. 定时采集与初次导入

| 任务 | 默认节奏 | 界面承诺 |
| --- | --- | --- |
| 模型公告、官方更新和工具生态 | 每 60 分钟检查 | 显示上次成功检查和下次计划时间 |
| GitHub 项目发现、仓库快照与 Release 检查 | 每 6 小时检查 | 显示检索范围、快照时间和同步延迟 |
| 立即同步 | 加入同一任务队列，合并重复请求 | 展示排队/执行状态，不能绕过限流；刷新列表仅重读本站数据 |

- 首次公告导入默认回看 7 天，每源单次最多处理 100 条，再分页/分批继续；记录待处理量和实际覆盖范围，不假定订阅源保留全部历史。仓库首次记录建立资料和当前版本基线，历史 Release 不作为刚发生的动态；后续按真实发布时间处理增量，历史补入明确标记。
- 首次 GitHub 发现最多保留 100 个候选仓库，按界面明示的主题与检索条件选取；不限于新建仓库。第一次记录只建立当前 Star 基线，不补造过去快照。
- 发布日期未知的条目按首次发现时间排序，明确“发布时间未知，发现于…”并可按时间未知筛选，不伪装成近 7 天发布的新闻；新接入来源显示实际覆盖范围与首次导入完成时间。
- 后续采用增量标识与内容变化检测；重复执行不制造新条目。停机恢复允许补采来源仍提供的内容，无法补齐的区间标记为覆盖缺口。
- 保持来源间独立状态；单源失败不阻断整站。遵守服务端重试时间、配额和退避要求，推迟任务时明确显示延迟原因，不承诺整点实时同步。同步延迟的两个计划周期阈值、暂停及首次同步规则以主文为准。

GitHub 的搜索另有限额与每查询最多 1,000 条结果边界，不能靠翻页声称覆盖完整结果；可能不完整的结果标记为“部分结果”。条件请求、缓存和限流处理参照 [Search 文档](https://docs.github.com/en/rest/search/search)、[速率限制](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api) 和 [官方最佳实践](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api)。

## 4. 自动入站与人工修正

1. 获取公开来源后提取标题、来源链接、稳定标识、时间及来源摘要，并按明确规则分类；来源摘要缺失时显示“来源未提供摘要”，不能生成假引用。
2. 通过来源验证、字段校验和确定性去重的条目自动进入信息流，不要求逐条人工审批；列表保留“自动汇总”来源标识。
3. 疑似重复、来源不可核验、缺少标题/有效原文链接、关键说法与证据不一致的条目进入“需核对”，附明确原因；缺少精确时间本身不等于抓取失败。
4. 人工可修正标题、摘要、分类、标签与事件关联，也可合并、忽略或恢复。人工修改单独保留，后续同步只更新来源记录，不覆盖人工字段。
5. 来源内容改变时标注“原文有更新”，用户可比较并选择采用；恢复自动字段值需显式操作。来源事实、人工注释和系统判断在详情中可区分。

收藏、已读和人工忽略等个人状态不被再次采集重置；已忽略的同一来源条目不能因新一轮同步重新出现，用户可显式恢复。

规则分类与来源摘要处理是必需能力；AI 中文摘要、翻译和辅助分类为可选增强。AI 不可用、超预算或调用失败时，仍照常完成采集、规则分类与合格条目入站。AI 内容标注生成方式和时间，提供原文入口；不得添加原文没有的参数、性能结论或发布日期。用户私有备注不随公开来源默认发送给第三方。

## 5. 时间、版本事件与重复关系

- 分开保存来源发布时间、来源修改时间（若提供）、首次发现时间、最后成功同步时间；精确时间按 UTC 语义保存，界面按 Asia/Shanghai 展示。
- 原文只有日期时保留日期精度与原始表述；来源未提供时区时不推算虚构的精确时间。抓取时间不能冒充发布时间。
- RSS 优先用来源内 GUID；网页用规范链接与事件标识；GitHub 用稳定仓库 ID 和 Release ID。仓库重命名不新建同一个项目。
- 同一源内容修订更新其版本记录，不重复发新卡片；不同来源对同一事件的报道合并为关联来源，原始证据仍可查看。
- 模型首次发布、预览转正式、价格变化和停用是不同事件；不能只因模型同名而合并。GitHub 不同 Release 是不同事件，预发布必须明确标注；普通 Git tag 不等于 Release。
- 自动合并仅用于标识明确一致的情况；语义相似但身份不明的条目进入“需核对”。人工合并保留原记录和来源关系，可撤销。

## 6. GitHub “关注增长”的含义

- 排序范围限定为本系统已采样的公开 AI 仓库集合；列表显示主题条件、采样数量、更新时间和覆盖限制，名称使用“关注增长”，不冒充 GitHub 官方 Trending。
- 净增 Star 只按同一稳定仓库 ID 的两次真实 `stargazers_count` 快照相减；负值如实保留，不把净增解释成新增关注人数或质量评分。
- “约 24 小时”和“约 7 天”以最新成功快照为终点，起点选不晚于目标时刻且最接近它的真实快照，偏离不超过 6 小时；展示实际起止与跨度。没有合格起点则不进入该窗口排行，可单独显示已有实际观察区间。
- 尚无历史基线、观察时长不足或缺少合格端点时显示“积累中/数据不足”，不把未知写成 0；中间单次缺测不使有效端点失效。终点延迟时保留旧数据并标注，不参与当前增长排行；不得通过模型推算补历史。
- 累计 Star、最近发布和关注增长分别排序；“有趣”由用途标签、项目简介和用户修正体现，不等同于高 Star 或官方推荐。
- [GitHub Trending 原榜](https://github.com/trending) 可作为人工导入的发现线索；只有保留观察日期、筛选范围和原榜记录依据时才标记“见于该榜”，否则仅作普通手动项目补充。原榜链接及导入时间不能单独证明历史上榜；其自动抓取不是首版强依赖，也不假设存在官方 Trending API。

## 7. 状态与移动端表达

| 状态 | 必须表达 |
| --- | --- |
| 尚未配置/首次同步中 | 当前还没有覆盖结果，不显示“今日无更新” |
| 检查成功、无新增 | 明确“本次无新增”，保留原有条目 |
| 筛选无结果 | 显示筛选条件和清除入口，不归因于来源失败 |
| 网络/解析失败 | 显示失败类型、重试状态和最后成功时间；保留旧数据 |
| 服务端限流/同步延迟 | 显示延迟和允许重试时间，未知恢复时间则如实说明 |
| 部分来源失败/结果不完整 | 显示受影响范围，其他来源内容继续可用 |
| 来源停用 | 停止未来任务，历史内容和用户收藏继续保留 |

桌面列表显示来源、事件类型、发布时间和主要项目指标；手机保留相同信息与操作能力，把全部来源、实际采样窗口、同步详情放入可点击详情。关键说明不依赖鼠标悬停；后台刷新不清空正在阅读的内容，也不重置滚动位置。

## 8. 内容可信度与存储边界

- “官方公告”仅代表来源归属，厂商自述标为“厂商公布”；二手消息或证据冲突标为“待核实”，不得自动提升为已确认事实。
- 保存必要的来源标识、标题、摘要、时间、变更指纹和核验依据；默认不全量镜像第三方原文、图片、代码仓库或下载资产，完整阅读跳转原站。
- 原文失效不删除个人收藏及已保存元信息；标明“原文暂不可访问”。停止来源采集与删除历史数据是两个独立操作。
- 外部文本、HTML、README、RSS 和模型输出均是数据，不得变成系统指令；渲染前按 [安全基线](../../SECURITY.md) 处理不可信内容。
- 上线采集前必须通过同一安全基线的 SSRF 门禁，包括重定向、DNS/IP 目标校验、出站边界、超时和大小限制；白名单不替代这些控制。

## 9. 实现验收要点

- [ ] 可验证的来源在计划任务执行后自动入站；AI 摘要关闭或失败时主流程仍可用。
- [ ] 重复同步不重复创建条目；疑似重复进入“需核对”；人工修正经再次同步仍保留。
- [ ] 时间精度、发布时间与采集时间可区分；初次历史覆盖不足和截断提示真实。
- [ ] GitHub 冷启动不显示增长；真实两次快照、负增长、窗口不足与缺测均有正确结果。
- [ ] 限流、失败、空结果、部分成功、停用来源分别呈现，旧数据与收藏不丢失。
- [ ] 桌面与手机都能查来源、查看摘要、收藏、修正和处理需核对项，无悬停专属操作。

本清单均为待实现验收项；候选来源在 2026-11-04 实际核验过入口，后续实现仍须复核可用性、内容使用规则和解析行为。
