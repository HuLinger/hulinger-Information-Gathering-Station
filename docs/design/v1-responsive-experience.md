# 首版双端信息架构与交互规格

日期：2026-11-04。状态：**首版已实现并完成本地双端检查，证据与未覆盖设备见 [设计验收](../../design-qa.md)**。

本文细化 [首版产品设计](v1-product-design.md) 的电脑与手机体验；产品范围、字段规则、刷新间隔、保留期限和热度计算口径以主文为准，不在此重复定义。
视觉继续遵守 [UI 规范](../ui-standard.md) 与 [现有设计变量](../../design/tokens.json)，统一使用 Ant Design；不引入第二套移动组件库。最终布局与实现依据见 [页面规格](v1-screen-specification.md)。

## 1. 入口与页面清单

产品是仅本人登录后使用的 AI 资讯集合工具。自动采集的内容直接进入站内视图，人工修正是阅读后的可选动作，不设置“必须审核后才看得到”的默认流程。

| 页面 / 入口 | 主要任务 | 内容与去向 |
| --- | --- | --- |
| 最新动态 | 快速了解新增资讯 | 汇总模型、开源项目及其他已启用 AI 来源的动态；进入内容详情或相关实体 |
| 模型更新 | 持续了解同一模型的变化 | 模型实体列表、近期事件、厂商与来源；进入模型时间线 |
| 开源项目 | 发现并追踪项目 | 仓库实体列表、项目简介、动态与可解释热度；进入项目时间线 |
| 我的整理 | 找回自己的处理结果 | 收藏、稍后读、归档、需核对、回收站五个分区；需核对内可筛选已排除并恢复 |
| 来源管理 | 管理收集范围与异常 | 已配置来源、采集状态、最近成功时间、失败原因、暂停和恢复入口 |
| 全局搜索 | 跨类型查找信息 | 独立搜索页；结果明确属于动态、模型还是项目，保留来源与匹配字段 |
| 内容详情 | 阅读、核验并整理 | 事实内容、摘要性质、来源、时间、关联实体和个人操作 |
| 实体详情 | 理解连续变化 | 模型或仓库的稳定身份、当前资料及可追溯事件时间线 |
| 修正表单 / 历史 | 更正分类与内容 | 原采集值、当前展示值、个人修正、保存结果与历史 |
| 设置 | 管理个人产品偏好与数据 | 展示主文已纳入首版的设置和数据操作；未实现能力不展示可操作入口 |

桌面侧栏依次为“最新动态 / 模型更新 / 开源项目 / 我的整理 / 来源管理”；全局搜索位于顶部常驻区域。
手机底栏固定为“动态 / 模型 / 项目 / 我的”；顶部提供带可访问名称的搜索入口，以及标明“更多”的头像菜单。
手机“更多”菜单明确列出“来源管理”和“设置”；“我的”页也提供这两个文字入口，不能仅通过无提示手势或不可辨认头像进入。
详情页提供明确返回入口；返回后恢复原分区、筛选条件与阅读位置，不能跳回未筛选首页。

## 2. 信息呈现优先级

| 层级 | 列表必须可见 | 详情补全 |
| --- | --- | --- |
| 识别事实 | 标题、类型、关联模型或仓库身份 | 事件描述、关联实体、原始来源标题；传闻或待确认信息有明确标记 |
| 核验出处 | 来源名称及可打开的出处 | 主来源与相关来源分别列出，保留原始链接；合并聚合不抹掉出处 |
| 判断时间 | 来源发布时间；未知时明确“发布时间未知” | 分别展示发布时间、采集时间、资料观测时间；不能把入库时间冒充发布日期 |
| 理解摘要 | 短摘要和“来源摘要 / AI 摘要 / 人工整理”等实际性质 | 规则提取属于来源摘要，详情说明范围；只有启用并真实执行 AI 摘要时才标为 AI 摘要 |
| 判断热度 | 指标名称、统计窗口或观测时点、数据来源 | 自定义关注增长展示比较依据；GitHub Trending 展示榜单出处、时间与筛选条件 |
| 个人整理 | 收藏、稍后读等已有状态和入口 | 标签、备注、归档、删除与恢复；避免让个人状态看起来像来源的客观结论 |

内容以事实和出处优先，热度只作辅助排序依据。“自定义关注增长”与“GitHub Trending”分别标记，不能以站内计算冒充官方榜单。
尚无可比采样时显示“数据不足”；指标采集失败显示缺失原因，不用零代替未知。GitHub Trending 若未接入，不展示伪造榜单或可用开关。
模型版本号、发布时间、GitHub 指标不得用看似真实的“最新示例”填充。设计演示只能使用显式合成内容，并标明“示例数据”。
列表优先显示稳定事实与短摘要；来源、摘要性质、时间和重要陈旧提示不能因为手机屏幕较小而全部折叠隐藏。

## 3. 电脑与手机的操作分工

| 能力 | 电脑 | 手机 |
| --- | --- | --- |
| 浏览资讯 | 列表或信息行，可同时浏览筛选区与详情 | 单列信息卡；先标题与事实，再摘要与个人操作 |
| 查看详情 | 支持并排阅读；始终可进入完整详情页 | 独立详情页，保持明确返回路径和可到达操作区 |
| 筛选排序 | 常用条件常驻，其余展开 | “筛选”按钮展示已选数量，抽屉选择并应用；当前条件以可移除标签可见 |
| 批量整理 | 明示复选框和已选数量，批量收藏、归档等依主文范围提供 | “管理 / 多选”显式入口；选择后提供同等核心动作，不依赖长按才能发现 |
| 收藏与稍后读 | 信息行与详情均可操作，状态即时可辨 | 阅读时直接可达；动作有文本或可访问名称，不仅靠颜色变化 |
| 人工修正 | 可对照原值编辑；复杂字段使用完整表单 | 默认先展示常用字段；“完整编辑”进入单列表单，不能永久隐藏核心字段 |
| 来源与故障 | 查看各来源状态并定位失败条目 | 从“更多”或“我的”进入，同样能暂停、恢复、重试和查看原因 |
| 数据与设置 | 通过设置进入主文规定的核心操作 | 同样可进入完整页面；需要等待的任务显示状态和结果入口 |

手机减少同时显示的信息，不减少核心能力。删除、恢复、来源管理、完整编辑不能成为只能回到电脑完成的操作。
批量动作明确作用于“已选条目”；跨页全选若支持，必须单独确认范围。筛选变化不能悄悄把旧选择应用到新结果。
归档、收藏和稍后读按主文定义分别表示整理状态，不创建内容副本；同一条目从不同入口进入时保持一致。
回收站突出恢复入口；永久删除明确不可恢复范围，二次确认后才执行；返回列表必须反馈真正结果。
“需核对”提供归类入站、关联已有事件和排除动作，手机与电脑均可完成；“已排除”筛选提供找回入口。合并/拆分预览个人整理冲突并保留撤销关系，遵循主文规则。

## 4. 搜索、筛选与实体时间线

全局搜索从任何主分区均可进入；搜索页明确当前范围，可切换全部或内容类型。各页面复用同一套条件名称、值和清除行为。
共有条件包括主文定义的内容类型、来源、时间、标签与个人状态；实体页增加实体范围，不能把“模型发布事件”和“模型实体”混为一种结果。
不同筛选维度组合时取交集，同一可多选维度内取并集；特殊例外必须在控件说明。日期范围使用统一时区并明确筛选的是发布时间还是采集时间。
结果数量、当前排序和生效条件始终可获知；“清除全部”与移除单项都可用。查询词与个人筛选状态默认保存在会话，不擅自进入共享 URL 或遥测。
模型详情以稳定模型身份组织资料与事件；项目详情以仓库身份组织发布、维护和热度观测。时间线各事件保留自身来源及事件时间，发布时间未知时单独标识。
来源后续修订、项目更名或人工更正通过关联和记录呈现；不能把旧条目直接改成新事实而丢失上下文。刷新产生新内容时提示可查看，避免正在阅读的行突然重排。

## 5. 阅读、收藏与人工修正流程

1. 进入最新动态或某实体时间线，查看事实、来源和时间；有异常或摘要不确定性时先看到相应标记。
2. 打开详情阅读，必要时打开原始来源核对；返回仍保留阅读位置。
3. 收藏或加入稍后读，成功后展示已保存状态，并可在“我的整理”找回；失败时保留原状态和重试入口。
4. 发现标题、归类、实体关联或摘要需要修正时进入“修正”；看到原采集值与当前值，再修改允许人工覆盖的字段。
5. 保存后显示“已人工修正”和记录入口；原采集证据保留。后续自动采集不得静默覆盖人工修正，需要对比时给出差异及处理入口。
6. 放弃编辑返回原页面；存在未保存内容时先提示。网络失败保留本次输入；发生并发更新时提示冲突并允许对照选择，不无声覆盖。

收藏、稍后读与修正均为可选步骤，阅读不必先整理。采集错误不自动转为个人待审核任务；只有需要本人决定的冲突才进入明确的待处理提示。

## 6. 自动收集与异常状态

| 状态 | 页面反馈 | 本人可以做什么 |
| --- | --- | --- |
| 首次尚无内容 | 区分“未配置来源”“等待首次采集”和“已采集但无条目” | 进入来源管理或查看任务状态；不把加载中的页面说成空数据 |
| 后台采集中 | 保留已加载内容，显示最近成功时间与当前进度状态 | 继续阅读；新条目完成后选择查看 |
| 部分来源失败 | 汇总页提示覆盖不完整，来源页列失败来源及原因 | 查看受影响范围、重试或暂停；其他成功内容继续可读 |
| 限流 / 鉴权失败 | 说明可重试时机或配置问题，显示脱敏原因 | 按允许范围重试、更新配置；不暴露凭据或内部堆栈 |
| 信息陈旧 | 资料或热度处显示观测时间及陈旧标记，阈值依主文 | 查看上次成功资料、打开来源核对；陈旧不等于内容必然错误 |
| 原文不可访问 | 保留已采集的允许保存内容与出处，说明无法访问 | 阅读已有资料、重试打开、补充个人备注 |
| 单条解析失败 | 来源任务显示失败数量和可定位的脱敏原因 | 查看原链接、人工补录或修正；不能凭空生成成功摘要 |
| 会话失效 / 设备断网 | 区分需要重新登录与网络中断，明确保存是否成功 | 恢复登录或网络后重试；私有内容不出现在未授权页面 |

“最后尝试时间”与“最后成功时间”分开显示。站点总体正常不代表所有来源都已更新；成功状态必须说明实际覆盖范围。
未接入的来源标记为未配置或不展示；首版没有的重试、导入、摘要等能力不能以假按钮暗示已可用。

## 7. 后续实现的验收矩阵

| 检查方式 | 关键场景 | 合格条件 |
| --- | --- | --- |
| 桌面截图 | 最新动态、实体时间线、批量整理、修正、来源异常 | 信息层级和 token 一致；事实、来源、时间可辨；范围与状态清楚 |
| 手机截图 | 底栏四入口、全局搜索、更多菜单、详情和完整编辑 | 来源管理可发现；主操作可达；无内容溢出或被底栏遮挡 |
| 视口与缩放 | 使用 UI 规范的全部适用尺寸、长中英文、空结果及错误状态 | 内容重排、关键条件可见；必要内容和功能不因缩放消失 |
| 触控 | 收藏、稍后读、筛选、多选、修正、恢复、来源管理 | 点击区域符合 UI 规范；不依赖悬停、长按或精细拖动完成核心操作 |
| 键盘与读屏 | 导航→搜索→详情→收藏→修正；弹窗与抽屉打开关闭 | 顺序合理、焦点可见且归还；结果状态可感知；无键盘陷阱 |
| 数据与失败 | 聚合去重、资料陈旧、部分采集失败、保存失败、修正冲突 | 出处与人工修正保留；未知不伪造；错误不误报成功；输入可恢复 |
| 双端一致性 | 电脑收藏后手机查看，手机修正后电脑重读 | 已成功持久化的内容和个人状态一致；并发差异有明确处理 |

验收截图只使用合成或经审查的脱敏数据，并记录视口、状态与提交。当前文档不包含上述检查的执行证据，也不表示应用已经可用或达到上线条件。
