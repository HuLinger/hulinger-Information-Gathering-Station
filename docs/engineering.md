# 开发与质量规范

状态：初始基线，2026-11-04。应用代码尚未建立；本文件规定引入代码时必须完成的工程条件。

## 工程决策

- 优先单体应用或模块清晰的单仓库，先控制个人维护成本；拆服务必须有明确容量或组织收益。
- 前端采用支持 Ant Design 的技术方案；应用框架、数据库、部署平台及其版本由 ADR 确认，禁止仅因模板方便就隐式决定。
- TypeScript 前端启用严格类型检查；服务端语言按最终方案使用对应静态检查。数据校验必须在服务端执行，不能依赖 TypeScript 类型保证外部输入。
- API 明确请求/响应、分页、排序、错误格式和授权规则；不向客户端返回内部堆栈。写入必要时采用事务与幂等控制。
- 数据库变更使用版本化迁移；禁止在生产手动改表后不留迁移。删除字段或转换数据先制定恢复方案。
- 界面、业务规则、数据访问分层，鉴权与授权集中维护；共享代码在真实重复出现后提取。
- 包管理器只保留一种，应用依赖引入时提交对应锁文件。CI 使用可复现安装，依赖新增须说明用途和维护情况。
- 当前 `package.json` 只用于规范工具，不代表应用技术栈已经确定。工具没有第三方依赖，因此无需安装步骤。

## 文件与代码约定

- UTF-8、LF、文件末尾换行，文本不得包含行尾空格；仓库已提供 EditorConfig 和 Git attributes。
- 名称表达业务意图；函数职责清楚，错误必须处理。注释说明原因、边界与取舍，不重复代码。
- 业务文案集中管理，首版简体中文。时间、数字和错误提示保持一致。
- 环境变量只提交不含真实值的 `.env.example`；新增配置说明含义、默认值、必填性以及是否只能在服务端使用。
- 日志带请求标识、严重程度、事件与耗时；不得记录正文、访问令牌、密码、完整导出或含凭据的 URL。
- 不添加空测试、永远成功的构建脚本或无意义占位接口来通过 CI。

## 检查分层

| 阶段 | 必须运行的检查 |
| --- | --- |
| 当前规范阶段 | `npm run check`；提交时检查暂存快照与提交消息；远程 PR 检查分支和标题 |
| 首次引入应用 | 接入真实格式/lint、类型检查、测试与生产构建，并加入 CI；仓库规范检查继续保留 |
| 业务开发 | 业务规则与边界用单元测试；数据库/权限用集成测试；关键用户流程用端到端验证 |
| UI 变更 | 指定尺寸截图、加载/空/错误状态、键盘操作、对比度及无障碍检查 |
| 数据/部署变更 | 新建数据库与升级现有数据库验证，恢复/回滚验证，配置完整性及预发布冒烟 |

重点覆盖登录拒绝、越权访问、保存持久化、组合筛选、软删除/恢复、导出/导入和异常处理。修复缺陷优先增加能够复现问题的测试，不为覆盖率数字编写与实现同构的测试。覆盖率阈值在应用建立时按模块风险设置。

## 体验与性能预算

以下为项目初始验收预算，并非当前性能承诺，也不声称是 Ant Design 的官方标准：

- 首版覆盖 10,000 条合成信息；带分页的列表及常用搜索接口在预发布约定环境下 p95 ≤ 500ms（不含客户端网络）。测试记录硬件、数据库索引、数据分布和查询样本。
- 主要页面按约定的移动设备和网络配置测试；LCP ≤ 2.5s、CLS ≤ 0.1，真实用户有足够样本后评估 INP ≤ 200ms，按移动端/桌面分别统计第 75 百分位。首版可用实验室交互测量辅助，不能冒充真实用户指标。
- 长列表分页或虚拟化，搜索有合理节流/取消机制；页面不得为显示第一页一次请求全部内容。
- 预算失败时定位原因、说明取舍并记录修订决定；禁止只通过换更强测试机器来掩盖回归。

## 完成定义

- 需求的正常、边界和失败情形都有可观察的正确结果。
- 数据真实持久化；刷新或重新登录不会丢失已确认保存的内容。
- 权限在服务端生效，输入和输出按数据类型处理。
- 适用检查实际通过，PR 记录命令、环境和结果；未运行的检查明确标注。
- UI 符合统一规范，测试截图不包含个人真实数据。
- 必要文档、迁移、环境说明和用户可见变更记录同步更新。
- 生产发布额外满足 [上线门禁](production-readiness.md)；代码合并不自动等于允许部署。

性能指标参考：[Web Vitals](https://web.dev/articles/vitals)。阈值用于本项目目标，测试方法和实际样本必须另行记录。
