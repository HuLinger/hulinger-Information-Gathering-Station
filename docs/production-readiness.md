# 生产就绪与发布规范

生效日期：2026-11-04。定位：个人私有信息集合工具，按可长期运维的上线项目建设。

当前阶段只有项目规范、工程治理基线和首版产品设计，尚未建立业务应用、生产服务或线上分支保护。本文的检查项均为待实施门禁；没有证据不得标记通过。安全要求以 [SECURITY.md](../SECURITY.md) 为准，UI 验收以 [UI 规范](ui-standard.md) 为准。

## 1. 环境与配置

| 环境 | 用途 | 数据与权限 |
| --- | --- | --- |
| development | 本地开发和自动化测试 | 合成数据、开发凭据，不接生产数据库 |
| staging | 发布候选验证、迁移和恢复演练 | 独立数据库/存储/密钥；只使用合成或经过审查的脱敏数据 |
| production | 个人实际使用 | 私有业务数据、最小权限账号、独立凭据与备份 |

三个环境可以由同一托管平台承载，但数据、凭据和访问边界必须隔离。每个配置项记录名称、用途、是否敏感、环境范围和缺失行为；关键配置缺失时启动失败，禁止悄悄回退到生产或不安全默认值。配置样例不含真实值。

生产使用受支持的运行时版本和锁定的依赖。构建产物须对应确定的 Git 提交；预发布验证与生产发布使用同一产物或可验证一致的构建输入。禁止在服务器直接修改业务代码后绕过版本记录。

## 2. 质量门禁

业务代码首次合并前配置实际技术栈对应的格式、静态分析、类型检查（适用时）、构建和测试命令；不允许用空脚本假装通过。后续每次合并按变更范围执行，但以下关键路径必须有可重复验证：

- 未登录拒绝访问；合法拥有者可访问；其他身份不能读取或修改数据；退出后旧会话失效。
- [项目章程](project-charter.md) 首版范围中的创建、编辑、收藏、搜索、分类或标签、归档、删除及恢复均须验证；不能以“尚未实现”为由略过必需能力。失败不得显示假成功或造成不可察觉的数据丢失。
- 首版必须验证数据导出的格式、编码、权限和完整性；导入启用时追加重复处理、部分失败报告及往返完整性验证。未实现的可选能力不展示可操作入口。
- 首版自动采集须验证关闭浏览器后的定时执行、重复运行去重、来源限流/失败、人工修正保留、缺失时间与热度窗口。全部采集来源通过 SSRF 与不可信外部内容门禁。
- 数据迁移、备份恢复与关键安全负例；导出覆盖来源、事件/实体关系和个人整理状态。
- UI 的键盘操作、可访问性、响应式与状态覆盖，保留可复核截图和结果。

首次有远程仓库后，主分支必须启用 PR 和必要 CI 检查，禁止强制推送与删除；远程规则实际配置完成前，只能称“规则已定义”。个人维护采用有证据的自审；以后有协作者时追加独立审查。基础规范检查通过不能替代应用构建、业务测试、安全检查或上线验收。

## 3. 数据迁移、备份与恢复

- 数据结构变更提交有顺序的迁移文件；禁止靠生产手工改表维持结构。预发布先验证迁移、失败行为和应用兼容性。
- 优先采用向后兼容的新增—迁移—清理步骤。破坏性迁移必须列出影响、备份点和恢复办法；迁移失败时停止发布，不能继续启动不兼容版本。
- **应用回滚**是重新部署上一验证过的产物；只有数据库结构仍兼容时才成立。**数据库恢复**是从备份恢复数据，会影响备份点之后的写入，不能把回退代码当成恢复数据。
- 首次发布没有上一生产产物，应先验证撤下服务或关闭入口的操作，以及恢复初始化前快照/空库的路径；一旦已经接收真实数据，先保护现有数据并评估恢复点后的写入，禁止直接清空数据库。之后的发布才要求保留上一健康产物。
- 初定恢复目标：RPO 不超过 24 小时（允许丢失的数据时间窗口），RTO 不超过 4 小时（确认故障到恢复可用的时间）。这些是项目目标，尚非已实现保障；首次演练测量后确认是否可达。
- 至少每日备份，并在破坏性迁移前额外备份。备份包括数据库、附件和恢复所需配置说明；加密传输与存储，保存在独立于应用实例的故障域，访问凭据最小化。
- 初定保留策略为每日副本 7 份、每周副本 4 份；密钥与备份分开保管，恢复人员能取得密钥。策略变更在决策记录中说明成本与恢复影响。
- 首次上线前及之后每季度、数据库/备份机制重大变更后，向隔离环境执行恢复演练；核对记录数、抽样内容、附件完整性和登录后的关键操作，记录耗时与可恢复时间点。
- “备份任务执行成功”不能替代恢复成功。个人导出是用户能力，不能代替自动备份。
- 备份包含来源配置、事件/实体关系、个人覆盖、去重/排除标识、同步进度与项目观测；恢复后先暂停采集核对游标，再重放任务验证不重复入站、不复活已排除内容。

上述频率、保留期与恢复目标是本项目初定运维要求，须由实际托管方案落实。

## 4. 监控与日常运维

采用适合个人维护的轻量方案，至少覆盖服务存活、业务就绪、异常、证书到期、存储空间与备份新鲜度。存活检查不依赖数据库；就绪检查反映必要依赖状态。公网健康响应只返回最小状态，内部细节受访问控制。

初定规则：每 5 分钟探测一次；连续 3 次失败通知维护者；备份超过 26 小时未成功通知维护者；存储使用率超过 80% 和证书剩余 14 天触发告警。上线前确定通知渠道并实际发送一次演练告警，记录收到时间。阈值可根据实际误报和成本调整，变更须留记录。

采集监控额外覆盖来源最后成功时间、排队/失败任务及限流；超过 [首版设计](design/v1-product-design.md) 定义的两个计划周期未成功时显示来源延迟并通知维护者，暂停和未初始化状态另行处理。网站本身健康不能掩盖采集长期停止。

错误记录包含时间、环境、发布提交、请求标识和脱敏原因；前端只展示可操作的错误提示，不暴露堆栈与连接信息。初定应用日志保留 14 天、安全及发布操作记录保留 30 天，自动轮转并限制访问；任何真实业务正文都不进入日志。[OWASP Logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)

每月检查依赖更新、证书/域名、容量与费用；告警发生后按“确认影响—限制损害—恢复—验证—记录原因与改进”处理。

## 5. 首次上线门禁

每项必须附提交、命令输出、脱敏截图或演练记录；不适用项写明原因和适用条件。部署前完成前九项，部署后完成最后一项；全部完成后才能记录“成功上线”。业务必需项不能标记不适用。

- [ ] 产品首版范围已确定，数据结构与技术选型已记录；所有占位内容和假数据有明确开发环境边界。
- [ ] 独立远程仓库已建立，分支保护和必要 CI 检查已实际生效；发布提交与产物可追溯。
- [ ] 开发、预发布、生产隔离完成；配置缺失、权限不足等启动失败行为已验证。
- [ ] 拥有者身份、登录限速、会话撤销、服务端授权、私有存储及 HTTPS 已验证。
- [ ] 密钥扫描与依赖风险评估完成，无未处理的发布阻断问题；日志与监控脱敏已抽查。
- [ ] 相关静态检查、构建、自动采集及人工整理关键路径、安全负例通过；电脑和手机的 Ant Design UI、状态一致性与可访问性验收有证据。
- [ ] 迁移在预发布成功；首次发布的撤下及初始化恢复路径已验证，后续发布的上一健康产物和兼容回滚路径可用；破坏性变更恢复方案明确。
- [ ] 自动加密备份与异地/独立故障域存储已配置；隔离恢复演练通过并记录 RPO/RTO 实测值。
- [ ] 域名、HTTPS、健康探测、告警接收、日志轮转、容量及费用上限已验证。
- [ ] 生产发布记录填写完整；发布后完成登录和一条合成记录的创建、查询、修改与清理，确认无私人内容泄漏。

## 6. 发布与回滚顺序

1. 从满足分支规则的确定提交生成发布候选；执行 CI，保留结果与产物标识。
2. 部署预发布，验证业务、UI、授权、迁移和回滚条件；填写本次发布证据。
3. 检查备份及恢复点；按需要安排写入暂停，执行已验证的生产迁移与部署。
4. 验证 HTTPS、健康检查和拥有者关键路径，观察错误；成功后更新发布记录。
5. 出现授权失效、核心路径不可用或数据完整性风险时停止扩大变更。首次发布按已验证方案关闭入口、保护数据并恢复；后续发布结构兼容则回退应用产物，结构不兼容时先限制写入，按已演练方案修复或恢复数据库，并核对恢复点之后的数据影响。

## 7. 发布证据模板

每次发布保存一份不含密钥和私人内容的记录；原始日志或私密基础设施标识保存在受限位置，只引用脱敏证据。

```text
发布时间（Asia/Shanghai）：
操作者：
发布标识 / Git 完整提交：
构建产物标识或摘要：
本次可见变化与影响范围：
CI、业务、安全及 UI 验证结果和证据位置：
预发布验证时间与结果：
迁移列表及兼容性说明：
最新可恢复备份时间 / 恢复演练记录：
上一产物（首次注明不适用及撤下方案）/ 应用回滚步骤 / 数据恢复步骤：
已接受风险、补偿措施、责任人和到期日（如有）：
生产健康、合成记录冒烟与告警验证结果：
发布结果 / 回滚结果 / 后续处理：
```
