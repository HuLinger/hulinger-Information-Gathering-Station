# 项目章程

状态：初始基线。日期：2026-11-04。产品负责人：Hulinger。

## 目标与原则

这是自己长期使用的信息集合工具，部署后可在受保护的网络入口访问。核心价值是把分散的信息集中管理，并能快速找回、使用和带走自己的数据。私有性、可靠性、易用性和可维护性优先于功能数量。

用户已确认三项硬约束：使用 Git 管理版本与分支；UI 采用 Ant Design 体系；按上线项目建设，并在实现前明确规范。

## 初始业务范围

以下是根据「自用信息集合」确定的起步范围；具体字段、入口和优先级在实现前补充需求验收，调整通过变更记录完成。

| 范围 | 首版验收方向 |
| --- | --- |
| 信息收集 | 手动保存链接或文字信息，支持标题、来源和备注；保存后刷新仍存在 |
| 信息整理 | 支持分类或标签、编辑、收藏、归档；同一信息不因多标签重复创建 |
| 信息查找 | 支持标题/备注搜索及分类、标签、状态筛选；无结果有明确反馈和清除筛选入口 |
| 信息使用 | 能查看详情和打开来源；失效链接保留已保存内容，操作失败不误报成功 |
| 数据自主 | 可导出完整个人数据，格式有版本说明；如启用导入，须有重复处理规则和失败报告；备份恢复另按上线门禁执行 |
| 私有访问 | 只允许本人登录后访问内容、搜索、导出及附件；禁止匿名注册 |

首版不包含公共分享、多用户协作、推荐算法、付费系统、浏览器插件或任意网站自动采集。RSS、自动摘要、URL 元数据抓取、附件上传均作为后续需求单独评估；引入时补充权限、成本和相应安全控制。

## 信息与数据约定

- 明确信息的稳定标识、内容类型、标题、来源、创建/更新时间及状态；可选字段可为空，不用占位假值冒充真实内容。
- 业务时间统一存储为带时区语义的 UTC 时间；界面默认按 Asia/Shanghai 展示，可在后续需求中扩展。
- 保存、编辑、删除、导入需要有明确成功/失败结果。重复点击不得制造重复写入。
- 删除先进入可恢复状态，默认保留 30 天；永久删除须明确告知范围并二次确认。过期清理需要独立任务与运行记录，不能仅依赖页面隐藏。
- 导出须包含信息、关联分类/标签和必要元数据；有附件时须定义附件导出方式。导出不是数据库备份的替代品。
- 生产数据不用于演示、截图、自动化测试或错误日志。测试使用合成数据。

## 阶段与验收

| 阶段 | 交付要求 |
| --- | --- |
| 0：规范基线 | 规范可读、Git 边界正确、基础检查可运行；不等同于产品可用 |
| 1：可实现方案 | 数据模型、应用技术栈、身份验证与部署 ADR 完成，关键流程和验收条件明确 |
| 2：可用闭环 | 登录、收集、整理、搜索、归档/恢复、导出在持久化数据上通过验证 |
| 3：预发布 | UI、权限、错误处理、迁移、备份恢复与目标设备验证通过 |
| 4：生产发布 | 上线门禁全部通过，有版本标签、发布记录和回滚材料 |

## 范围与规范变更

小的实现细节在 PR 说明；改变业务范围、设计体系、数据存储、身份验证、部署或安全边界时，先写 ADR（背景、备选方案、决定、影响、验收和日期）。硬约束变更需要产品负责人确认。每个需求说明谁在什么场景完成什么操作，以及成功、失败和空状态；不以「做得像大厂」代替验收条件。
